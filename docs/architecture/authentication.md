# Authentication & Security Architecture — Project Atlas## 1. Visão GeralA camada de Autenticação e Segurança do **Project Atlas** (Fase 0E) estabelece a identidade criptográfica de usuários, controle de sessões ativas e isolamento estrito de recursos financeiros.A arquitetura adota o princípio de privilégio mínimo e defesa em profundidade:- **Hashing Robusto:** Senhas armazenadas com **Argon2id** (com proteção contra timing attacks).- **Access Tokens Efêmeros:** Tokens JWT assinados com HMAC-SHA256 e TTL de 15 minutos.- **Refresh Tokens Opaque e Stateful:** Chaves criptográficas de 48 bytes armazenadas sob hash HMAC-SHA256 com pimenta de servidor e rotação compulsória a cada renovação.- **Sessões Persistidas:** Rastreabilidade e revogação ativa no banco de dados (Session).- **Recuperação Segura:** Tokens de redefinição de uso único com expiração em 15 minutos e revogação geral de sessões após alteração de credencial.- **Isolamento de Recursos:** O userId é extraído unicamente do principal autenticado (@CurrentPrincipal()), e tentativas de acesso cruzado retornam invariavelmente 404 Not Found.---## 2. Fluxo de Autenticação e Ciclo de Vida de Tokens`mermaidsequenceDiagramautonumberactor User as Cliente (Web / Mobile)participant Auth as AuthController & UseCasesparticipant Hasher as Argon2PasswordHasherparticipant Token as TokenServiceparticipant DB as PostgreSQL (Prisma)participant Guard as JwtAuthGuard    %% Login    User->>Auth: POST /api/v1/auth/login { email, password }    Auth->>DB: Busca User por email normalizado    alt Usuário encontrado        Auth->>Hasher: verify(password, passwordHash)    else Usuário inexistente        Auth->>Hasher: verifyDummy() (tempo constante)        Auth-->>User: 401 AUTH.INVALID_CREDENTIALS    end    Auth->>Token: generateRefreshToken() & hashRefreshToken()    Auth->>DB: Cria Session com refreshTokenHash    Auth->>Token: generateAccessToken({ userId, sessionId })    Auth-->>User: 200 { user, accessToken, refreshToken, expiresIn: 900 }    %% Request Autenticada    User->>Guard: GET /api/v1/portfolios (Authorization: Bearer <accessToken>)    Guard->>Token: verifyAccessToken(token)    Guard->>DB: findById(sessionId)    alt Sessão ativa e não revogada        Guard-->>Auth: Injeta { userId, sessionId } no Request        Auth-->>User: 200 [Portfolios do Usuário]    else Sessão revogada ou expirada        Guard-->>User: 401 AUTH.SESSION_REVOKED    end    %% Rotação de Refresh    User->>Auth: POST /api/v1/auth/refresh { refreshToken }    Auth->>Token: hashRefreshToken(refreshToken)    Auth->>DB: findByPreviousRefreshTokenHash(hash)    alt Reuso detectado!        Auth->>DB: revoke(sessionId)        Auth-->>User: 401 AUTH.INVALID_REFRESH_TOKEN (sessão revogada)    else Token ativo válido        Auth->>DB: rotateRefreshToken(newHash, expiresAt)        Auth-->>User: 200 { accessToken, refreshToken, expiresIn }    end`---## 3. Componentes Centrais (pps/api/src/auth)### 3.1. Argon2PasswordHasher- Utiliza a biblioteca nativa rgon2 com variante rgon2id.- Implementa erifyDummy() executando uma validação contra um hash estático conhecido para garantir tempo constante contra credenciais inexistentes.### 3.2. TokenService- **Access Tokens:** Emissão e verificação de JWTs com sub: userId, sid: sessionId e TTL de 15 minutos (900s).- **Refresh Tokens:** Geração criptográfica com 48 bytes e hashing HMAC-SHA256 salpicado (REFRESH_TOKEN_PEPPER).- **Reset Tokens:** Geração de 32 bytes e hashing HMAC-SHA256 (PASSWORD_RESET_PEPPER).- **Validação de Ambiente:** Em modo production, exige segredos fortes e impede o uso de valores padrão de desenvolvimento.### 3.3. JwtAuthGuard & @Public()- Registrado como guard global no NestJS (APP_GUARD).- Todas as rotas são protegidas por padrão.- Rotas públicas (como /health, /ready e endpoints de login/cadastro/recuperação) utilizam o decorator @Public().- Valida o token e confirma que a sessão persistida no banco não foi revogada (  evokedAt === null) nem expirada.### 3.4. AuthenticatedPrincipal & @CurrentPrincipal()- Decorator de parâmetro que injeta { userId: string, sessionId: string } nos handlers de controller.- Elimina a necessidade de receber userId em query strings ou corpos de requisição.---## 4. Política Anti-Enumeração e Isolamento de Recursos1. **Enumeração de Usuários no Login:**   - Senha incorreta e usuário inexistente retornam exatamente a mesma resposta HTTP: status 401 Unauthorized, código AUTH.INVALID_CREDENTIALS e mensagem "Invalid credentials.".2. **Enumeração no Esquecimento de Senha:**   - O endpoint POST /api/v1/auth/forgot-password retorna invariavelmente { "accepted": true }, independentemente de o e-mail existir na base.3. **Enumeração e Invasão de Recursos Financeiros:**   - Caso um usuário autenticado tente consultar (GET), modificar (POST, etc.) uma Carteira, Conta ou Transação de outro usuário, a resposta da API é invariavelmente **404 Not Found** (PERSISTENCE.ENTITY_NOT_FOUND ou COMMON.NOT_FOUND).   - A API nunca emite 403 Forbidden para IDs de outros investidores, prevenindo a descoberta de identificadores válidos.---## 5.
