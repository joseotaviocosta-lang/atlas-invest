# ADR-023: Fluxo Seguro de Redefinição de Senha e Proteção contra Enumeração## StatusAprovado## ContextoO mecanismo de recuperação de senhas é um dos alvos mais frequentes em ataques cibernéticos, com riscos como enumeração de usuários, adivinhação de tokens, repetição de tokens antigos e manutenção de acessos indevidos em sessões previamente abertas.## Decisão1. **Endpoint POST /api/v1/auth/forgot-password Anti-Enumeração:**   - O endpoint aceita { "email": string } e SEMPRE retorna { "accepted": true } com status 200/202, independentemente de o e-mail existir ou não na base de dados.   - Nenhuma mensagem revela se o usuário foi encontrado ou se um e-mail foi disparado.   - Protegido por rate limiting rígido (máximo de 5 tentativas por minuto por IP) para impedir varredura em massa.2. **Geração e Armazenamento de Tokens de Redefinição:**   - Tokens de uso único gerados aleatoriamente via crypto.randomBytes(32) (64 caracteres hexadecimais).   - TTL estrito de 15 minutos.   - Armazenados na tabela password_reset_tokens exclusivamente em forma de hash HMAC-SHA256 com PASSWORD_RESET_PEPPER. O token em texto plano nunca é salvo.3. **Execução de POST /api/v1/auth/reset-password:**   - Aceita { "token": string, "newPassword": string }.   - O token é imediatamente marcado como utilizado (usedAt = now()), impedindo reuso.   - A nova senha é validada pelo PasswordSchema (mínimo 10 caracteres) e codificada via Argon2id.   - **Invariante Crítica:** Todas as sessões ativas do usuário são compulsoriamente revogadas (     evokeAllForUser), garantindo que qualquer sessão aberta anteriormente (em computadores públicos, celulares perdidos ou atacantes) seja desconectada imediatamente.## Consequências- **Positivas:**  - Impossibilidade de enumeração de e-mails via fluxo de recuperação.  - Inutilização imediata de tokens consumidos e proteção total contra replay.  - Desconexão preventiva completa de sessões potencialmente comprometidas.- **Negativas / Mitigações:**  - Usuários legítimos em múltiplos dispositivos precisarão fazer login novamente após a redefinição, o que é o comportamento de segurança desejado.
